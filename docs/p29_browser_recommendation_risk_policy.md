# P29: 브라우저 추천·위험고지 정책

## 범위

실제 `/answer` 브라우저 경로의 최종 사용자 행동만 보강한다.

- 변경하지 않음: corpus, BM25 retrieval, HCX 설정, Native Structured Outputs, citation validator
- 유지: original + primary provenance와 Fail-Closed citation 검증
- 변경: 추천성 질의의 생성 전 정책과 상품·세무·법률 고지 표시

## 추천성 질의 처리

다음 중 하나면 추천성 문맥으로 판단한다.

- `추천`, `골라`, `최고`, `가장 좋은`, `수익률 제일 높은`, `무조건` 등 단정/랭킹 표현
- 투자 기간, 위험 성향, 운용 목적 신호 중 두 가지 이상을 함께 제시한 투자성향 문맥

### 조건 부족

상품명을 생성하거나 추천하지 않는다. 다음을 되묻는다.

- 투자 기간
- 위험 성향
- 운용 목적

### 조건 충족

단일 상품을 최고·무조건 안전하다고 단정하거나 매수·매도를 권유하지 않는다. 원본 문서의 위험등급, 투자대상, 총보수 기준 후보 비교만 안내하고, 비교할 상품명/상품코드와 분산투자 여부를 추가로 확인한다.

이 정책 응답은 HCX를 호출하지 않는다. 따라서 모델이 안전 성향 사용자에게 주식형 상품을 단일 추천하는 경로를 막는다.

## 유형별 고지

| 질의 유형 | 표시 정책 |
|---|---|
| 상품 위험·보수·수익·투자대상 | 위험등급·투자대상·총보수·원금보장 여부는 원본 설명서로 확인하고, 실적배당형 상품을 원금보장처럼 단정하지 않는다는 고지 |
| 세금·과세·세액공제 | 개인 소득·계좌·수령 방식·적용 시점에 따라 달라질 수 있다는 고지 |
| 법률·압류·상속·소송 | 일반 안내이며 개별 법률 판단은 사실관계에 따라 달라질 수 있다는 고지 |
| 일반 제도 질문 | 상품·세무·법률 고지를 붙이지 않음 |

고지는 모든 답변에 일괄 추가하지 않고 해당 질의에만 추가한다.

## 검증

- 조건 부족 추천 요청은 HCX 호출 없이 역질문
- 투자성향 문장은 단일 상품 추천 대신 후보 비교 안내
- 상품 위험 질문은 위험 고지 포함
- 일반 제도 질문에는 불필요한 상품·법률 면책문구 없음
- 기존 API·EvidenceAssessor·질의 분석 회귀 통과

검증 결과: `203 passed`.

## 실행 반영

이미 실행 중인 FastAPI 프로세스는 코드 변경을 자동 반영하지 않는다. 브라우저에서 확인하려면 현재 서버를 종료한 뒤 `src.api.server:app` 기준으로 재시작해야 한다.

현재 API는 대화 이력을 보관하지 않는 단일 질의 API이므로, `이 상품 안전해?`처럼 상품명·상품코드가 없는 지시어 질의에는 임의 검색 결과를 답하지 않는다. 상품명 또는 상품코드를 확인한 뒤 위험등급과 원금손실 가능성을 원본 설명서 기준으로 안내한다.

## P29-B 실제 브라우저 Smoke

최신 `src.api.server:app`을 `HCX_MIN_INTERVAL_SECONDS=6`으로 재시작한 뒤 실제 `POST /answer` 경로에서 검증했다.

| 질문 | 결과 |
|---|---|
| 좋은 연금 상품 추천해줘 | HCX 미호출, 투자 기간·위험 성향·운용 목적 역질문 |
| 10년 투자, 공격적 성향이야 | HCX 미호출, 단일 추천 대신 후보 비교 안내 |
| 나는 안전한 게 좋아. 주식형 추천해줘 | HCX 미호출, 단정 추천 차단 및 조건 확인 |
| 이 상품 안전해? | HCX 미호출, 상품명 또는 상품코드 확인 |
| 세금 제일 적게 내는 법 알려줘 | 문서 기반 일반 안내 및 세무 고지 |
| DB와 DC 차이가 뭐야? | 문서 기반 답변, 상품·세무·법률 고지 없음 |

모든 요청은 HTTP 200으로 처리됐고, 정책으로 차단한 네 질의에서는 HCX 호출이 없었다.
